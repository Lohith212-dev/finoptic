# Finoptic — project context

*Read this at the start of any session in this directory. It exists so the user doesn't have to re-explain the project each time. Keep it current when things it describes change; see `status.md` for what's happening right now.*

**Formerly named "Meridian"** — renamed to Finoptic on 29 July 2026 (see `planning/01-branding-and-naming.md` for the naming process). Every visible "Meridian" string is gone, including inside the mock-up itself (title, sidebar wordmark). Only one filename — `planning/design-language/finoptic-design-language.md` — still carries the old name; a deliberate scope choice, not an incomplete rename.

## What this project is

Finoptic is a **product concept mock-up**, not a working application. It's a small set of plain HTML/CSS/JS files that open by double-click — no backend, no database, no auth, no build step, no framework, no real data connections. It exists to demonstrate, to a client, what a technology-spend / FinOps monitoring product could look like, before the real product is built.

**Always call it a "mock-up" or "prototype," never "the app" or "application"** — the user has corrected this explicitly; the real product doesn't exist yet.

## Immediate context

There is a **client call on Friday, 31 July 2026** to present this as a product concept. The mock-up's job on that call is to show the client they'll receive a service for monitoring their company's financial operations — not to demo finished software. See `status.md` for exactly where things stand relative to that date right now.

| `finoptic/index.html` | **The actual clickable mock-up — open this.** Carries the page title and an inline data-URI favicon generated from the logo mark (`finoptic/favicon-src.svg` is the unencoded source) — inline because a relative icon href is unreliable from a `file://` page. Double-click, no server or build step. Just the page shell; everything else is in the files below, loaded as plain `<script src>` tags. **The load order IS the dependency graph** — these are classic scripts sharing one global scope, not modules: `data → logo → finn-logo → icons → brands → core → components → tablekit → charts → tooltip → people → catalog → screens → the extra screen files → assistant-content → assistant → motion → shell`. Elements with `data-icon` / `data-logo` are filled in by `shell.js`. **Two files run something at load, not one:** `shell.js` boots the app at its foot, and `assistant.js` builds Finn's pod. That pod is deliberately all it builds — the panel needs `icon()`, which lives in `shell.js` and therefore does not exist yet, so the panel is mounted on first open instead. Don't "fix" that by moving the whole of Finn's boot into a `DOMContentLoaded` callback: that is the trap `tablekit.js` documents at length, because a listener that only works when it is attached late makes this load order stop describing the files. |

| `finoptic/components.js` | KPI tiles, `card()`, the briefing band, badges, `rowList()`, `table()` and legends. **Round 14 changed both ends of this file.** `kpi()` now takes `ytd:` and `spark:`, both **passed in by the screen** for the reason the strip's stats are (14.6): they mirror expressions computed from the renderer's own locals, and a second copy here would drift. Four things are also worth knowing. `table()` drives sorting and filtering off the **rendered cells** rather than the source data — see the note above it for why that is deliberate rather than lazy — and `tableOrder()` uses the same parser to give every table a **descending default sort on its largest-total currency column**; three tables opt out with `order:'keep'`. `kpi()` blanks a figure to an em dash when `workspaceEmpty()`, so a workspace that has closed no month never prints `$0K`; `emptyState()` picks its own cause for the same reason, offering **See how to connect** where a filter is not what emptied the card. And the briefing band's first cell is **derived, not authored** — `missedHTML()` runs a set of scored probes (concentration, timing, run-rate, fastest mover, tail, feed coverage, plus four screen-specific ones) and prints the one or two most notable, so the cell says what the tiles and the reconciliation strip cannot. | `finoptic/charts.js` | Every plot, as plain SVG, plus the `ENTITY` colour registry and the `--c1…--c8` ramp. Each chart emits invisible hit targets carrying `CHARTTIP.attrs(...)`. **`sparkline()` is the newest and the smallest** — 76×32px at a 2.6px stroke, inline beside a KPI figure, drawing **only the months the figure was computed from** (a first version drew all twelve dimmed, which put a year of movement above a quarter's number). Drawn in **`--c1`** — the accent under the default and Blue palettes, ink under Mono — so it themes by construction; §0.3's one-accent budget governs CHROME, and a sparkline is data ink like every other plot. Never a status colour, which is the fault that rule actually guards against. **Curved with `smoothPath()`, a MONOTONE CUBIC (Fritsch-Carlson)** — not Catmull-Rom, which overshoots, and an overshoot draws a month that never happened. **`lineChart()` and `bandChart()` take the identical curve**, because a curved sparkline over a sharp-cornered trend chart is two line treatments in one product — and on the finance screen it was the same series drawn two ways 400px apart. Every interpolated stroke carries **`class="cline"`**; `test-metrics.js` selects on that (brand marks are bezier paths too and would flood a `d*=C` selector) and checks all 184 lines / 1,430 segments against their anchors. Swapping in the naive tangent rule produces 84 failures, so the check has teeth. **Round 15 reversed how it plots.** `cumulative` is still accepted and is now **ignored** — a running total of positive months can only ascend, so two thirds of the board drew the same near-straight diagonal, and "month-on-month" is a request for exactly the movement accumulating hides. The axis is the series' own range rather than zero, with a guard: spread under **12% of the mean** draws flat instead of being stretched into false drama. Don't reinstate the accumulation — the objection it answered (a line ending at $9K under a figure of $96K) is answered instead by the hover readout, which names the month and its value. **`ranked()` is the descending sort**, applied inside `hbars()`, `donut()` and `legend()` rather than at the ~40 call sites — so every ranked list obeys at once and a runtime-loaded dataset cannot break it. `donut()` and `legend()` MUST run the identical comparator or the key mislabels the ring. `tail:true` pins a rolled-up remainder to the bottom. Time series and waterfalls are never sorted. |

## The data layer (done — this is how it works now)

Nothing in the mock-up is hardcoded data any more. The dataset arrives from `finoptic/data/scenario-*.js`, one active at a time, picked from the selector in the top bar; every screen re-renders from the new numbers. `RAW` is the dataset as authored, `D` is `RAW` after the active filters, and screens only ever read `D`.

A real `.json` file loads through **profile menu → "Load a dataset (JSON)…"**, which goes through an `<input type="file">` + `FileReader` — the only route that works from a `file://` origin, since browsers block `fetch()`/XHR of local files. **Export** writes CSV of the tables visible on the current screen plus the active dataset as JSON, and that JSON round-trips straight back through the picker. **Share** copies a URL encoding dataset + screen + view + filters.

The datasets are `.js` wrappers around pure-JSON payloads for the same `file://` reason. `finoptic/data/SCHEMA.md` holds the shape and the 14 invariants; `app.js` has a reconciliation guard that logs an error if a loaded dataset breaks them.

## Updating `status.md`

`status.md` is a living snapshot, not a changelog — update it (don't just append to it) whenever a **high-level item completes or the current focus changes** (e.g., a phase starts/finishes, a decision gets locked, the Friday plan changes). Don't update it for minor edits within an in-progress item. When updating, remove anything that's no longer relevant rather than leaving it to accumulate — the file should always read as "what's true right now," not a history log.
